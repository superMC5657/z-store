# ADR-0007: 开源清单仓库动态同步与客户端按需 API 详情拉取（含可配置 TTL 缓存）

- **状态**: Accepted
- **日期**: 2026-09-05
- **决策者**: 架构团队与用户共同裁决

## 上下文

纯静态打包且永久本地缓存的目录设计会导致三大问题：
1. **数据脱节**：上游开源软件发布新 Release、更新 Changelog 或修复安全漏洞时，详情与下载链接长期停留在旧版本；
2. **收录与客户端强耦合**：增删收录软件、调整分类或别称会受限于客户端发版周期；
3. **API 速率限制平衡**：需要在保障数据新鲜度的同时，控制 GitHub 未认证 60 次/小时配额的消耗。

## 决策

1. **开源清单仓库与离线种子兜底**：
   - 应用收录清单默认同步源指向独立生态清单仓库 `superMC5657/z-store-catalog`（由 `src-tauri/config.toml` 的 `[catalog].default_source_url` 声明，详见 ADR-0009）；
   - 客户端打包内置根目录 `catalog.json` 作为**离线种子兜底**，路径由 `src-tauri/config.toml` 的 `[catalog].local_path` 声明，全后端模块统一通过配置层接口读取；
   - 客户端启动及设置页支持增量同步远程最新清单（通道直连、不经加速前缀，结合 ETag 条件校验实现零成本热更新）。

2. **按需 API 动态拉取与 ETag 协商保鲜**：
   - 详情按 TTL + ETag 按需拉取，根据清单坐标请求上游 API 获取最新版本与构建资产；
   - 引入 **ETag 协商机制（`If-None-Match`）**：上游未发布新版本时返回 `304 Not Modified`，不消耗 API 配额并延长保鲜期；上游发布新版本时返回 `200 OK` 并更新数据库；
   - **更新发现与详情 TTL 解耦，按资产面/非资产面分治**：资产面（已安装应用、更新中心、收藏）仅手动触发网络——`fetch_app_latest_version_lightweight` 与 `check_for_updates` 默认只读本地（更新快照 → 详情缓存 → 收录库默认版本），仅显式手动刷新（`forceRefresh=true`）走 ETag 轻量探查并写 `update_results`，`get_cached_updates` 恒为 DB 快照读；非资产面（搜索/趋势/平台推导/图标/首页）默认自动拉取并经 ETag 条件请求复用（互补边界见 ADR-0019）。断网/限流失败时降级读取本地已有缓存。

3. **详情缓存保鲜期（TTL）**：
   - 详情 TTL 基线 60 分钟，由 `src-tauri/config.toml` 控制，设置页不暴露；
     后端保留 `{0, 10, 60, 360, 1440}`（分钟，`0` = 每次必向远端校验）挡位归一化，非法或越界输入（包括直接改库 / 备份导入）均归一化回退 `60`；
   - 项目基线参数及网络超时统一收敛于 `src-tauri/config.toml`（编译期嵌入二进制作为兜底，支持同级外部文件动态覆盖），不使用 `.env`；
   - 在 TTL 保鲜期内打开详情弹窗直接读取本地缓存（0ms 秒开）；超过 TTL 自动发起条件校验；
   - 详情弹窗提供显式「刷新」按钮，支持即时强制同步最新 Release。

4. **离线与弱网优雅降级**：
   - 当远端网络不可用或触发限额时，客户端自动降级为展示本地缓存数据，并在详情界面标注“离线缓存”指示，避免白屏或崩溃。
