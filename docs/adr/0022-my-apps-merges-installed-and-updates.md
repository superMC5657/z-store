# ADR-0022：「我的应用」合并已安装与更新视图，关注提醒归入收藏页

- 状态：Accepted
- 日期：2026-11-13
- 关联：ADR-0003（SQLite 持久化与 ETag 缓存）、ADR-0021（视图清单 `VIEW_TYPES`）
- 范围：前端（`VIEW_TYPES` 去掉 `updates`、`InstalledView` 承接更新动作、`FavoritesView` 承接关注提醒、侧栏角标、旧深链别名）；后端不变

## 1. 背景

原先「已安装」与「更新」是两个一级视图，列的却是同一批应用：更新页只是「已安装且有新版本」的子集。两页重复的地方：

- 已安装页能看到「有更新」徽标，却不能就地更新，要跳到更新页；
- 两页各有一个规则按钮，打开同一个规则管理弹窗；
- 锁定 / 隐藏在已安装页可开可关，在更新页只能开；
- 已安装页的「刷新」和更新页的「检查更新」都是刷新入口。

另外，更新页里的「关注动态」是**关注了但不一定装了**的应用发布新版本的提醒，和更新无关；关注列表本身又在收藏页「关注」签，同一件事分在两处。

## 2. 决策

### 2.1 一个「我的应用」视图

视图 id 沿用 `installed`（标签「我的应用 / My Apps」），`updates` 从 `VIEW_TYPES` 移除。`InstalledView` 接收更新快照与更新动作：

- **行内主按钮跟着状态走**：有可用更新的行显示版本差（当前 → 最新）、「更新日志」开关与「更新」按钮，「启动」收进更多菜单；其余行仍为「启动」。
- **一个更多菜单管所有规则**：锁定 / 隐藏用开关式动作（`handleToggleRuleFrozen` / `handleToggleRuleHidden`）；「跳过此版本」只在有更新的行出现。原更新页专用的单向 `handleFreezeVersion` / `handleHideApp` 随之移除。
- **筛选签**：全部 / 有更新 / 已锁定 / 已隐藏。已隐藏的应用只在「已隐藏」签出现，「全部」及其余签（含搜索结果）一律排除，「全部」计数也不含它们；它们的可用更新仍在快照里，行内照常显示版本差与「跳过此版本」。找不到路径的应用由 `get_installed_apps` 隐去，不设单独的签。
- **顶栏**：规则 / 扫描本地 / 检查更新，有可用更新时末尾再加「全部更新」；「全部更新」只升「有更新」签里的项。顶栏同时只有一个主按钮：有更新时是「全部更新」，否则是「检查更新」。不设更新提示横幅，可更新的行靠版本差与「有更新」筛选签识别；检查中在顶栏下方显示流式进度条。导出清单只在设置页提供。
- **刷新只留一个入口**：「检查更新」在联网检查的同时重读本地已装列表；检查期间沿用上一份更新快照，行的更新态不闪没。空列表态的动作是「扫描本地」。
- **不换行布局**：每行固定两行文字（标题行 / 元信息行），顶栏与筛选带各占一行，宽度不够时截断或收起，而不是换行：
  - 标题行名称先省略，版本与状态标记不收缩；元信息行的路径在胶囊内中段省略（目录段截断、文件名段保留）。
  - 行内动作簇宽度固定：「更新日志」只留图标，「卸载」与「取消管理」收进更多菜单，触发后整簇就地换成「确认 + 取消」。
  - 按所在面板 / 控制带 / 顶栏的实际宽度（container query）逐级收起：先藏安装方式标签，再藏安装日期与状态标签文字；筛选签横向滚动，排序按钮只留图标；顶栏极窄时按钮只留图标。
  - 窗口最小尺寸提到 1120×720（`tauri.conf.json`），常规缩放下不触发上述收起。

### 2.2 网络边界不变

「我的应用」属资产面：进入视图只读 `getInstalledApps` 与 `getCachedUpdates` 两份本地快照，零网络；联网仅经「检查更新」按钮手动触发（`handleCheckUpdates`：force 写库后重读快照）。

### 2.3 关注提醒归入收藏页

`watchNotifications` 改由 `FavoritesView` 消费：「关注」签顶部的「有新版本」分节（`WatchReleasesPanel`）列出待处理提醒，支持查看与「知道了」，无提醒时不渲染。有待处理提醒时收藏页落在「关注」签，页面打开后才到的提醒也会切过去；用户手动选过签后不再自动切换。已确认提醒的恢复仍在规则管理弹窗「关注已读」签，规则入口在「我的应用」顶栏与设置页。

### 2.4 侧栏与深链

- 侧栏「我的应用」角标显示可用更新数，而不是已装总数：可操作的数字更有用；为 0 时隐藏。口径与页内「有更新」筛选签一致：按平台筛选后，只数有已装行的更新项。
- 深链 `zstore://view/updates` 经 `resolveViewTarget` 的别名表解析为 `{ view: 'installed', focus: 'updates' }`：进入「我的应用」并落在「有更新」签。别名只用于外部入口，`ViewType` 联合与 `isViewType` 不认 `updates`。

## 3. 后果

- 更新相关文案从 `updates.*` 迁到 `installed.*`，关注提醒文案迁到 `favorites.*`，`updates` 命名空间删除。
- 关注提醒不再计入任何侧栏角标；收藏页的「有新版本」分节标题带数量角标。
- 更新快照只排除已锁定的应用，隐藏应用的更新保留在快照里供「已隐藏」签与规则管理跳过版本。「有更新」口径由 `selectUpdatableInstalled` 统一给出：有已装行、未隐藏、且通过平台筛选的更新项。筛选签计数、侧栏角标与「全部更新」的目标都取它，被平台筛选或隐藏规则排除的应用不会被「全部更新」顺带升级。
